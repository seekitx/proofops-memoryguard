# 编译与测试踩坑记录

## 2026-09-01 — Python 测试缺少 Keccak 后端

- 适用环境：macOS arm64，Python 3.11.15，项目 `.venv`。
- 执行命令：`.venv/bin/python -m pytest`
- 耗时或表现：约 0.8 秒结束；20 项测试中 19 项通过、1 项失败。
- 原因：`eth-utils` 会调用 `eth-hash` 计算 Base 交易函数选择器，但原依赖只安装了
  `eth-hash` 外壳，没有安装 `pycryptodome` 或 `pysha3` 哈希后端。
- 解决办法：在正式依赖中加入 `eth-hash[pycryptodome]>=0.8,<1`，确保开发、部署和
  干净环境都具备 Keccak 实现。
- 下次更快的做法：首次安装后先确认 `pycryptodome` 随项目依赖进入隔离环境；不要只在
  当前机器临时安装，否则部署环境仍会复现。
- 最终验证结果：补装 `pycryptodome 3.23.0` 后，同一命令重跑完成，`20 passed in
  0.09s`。

## 2026-09-06 — npm 合约锁文件解析受代理超时影响

- 适用环境：macOS arm64，Node `v22.23.0`，npm `10.9.8`，冻结发布 worktree。
- 执行命令：`npm install --package-lock-only --ignore-scripts --no-audit --no-fund`
  （`contracts/`）。
- 耗时或表现：约 2 分钟内连续 registry metadata 请求每次约 70 秒并返回
  `FETCH_ERROR`；命令未生成锁文件，随后主动停止，避免无依据继续等待。
- 原因：npm 用户配置把 `proxy` 与 `https-proxy` 指向本机 SOCKS
  `127.0.0.1:7890`，当前链路访问 `registry.npmjs.org` 不稳定。
- 解决办法：仅为本次命令显式指定可达的临时 registry/proxy 参数，保留全局 npm
  配置不变；生成后审查 lockfile 的包版本、integrity 和依赖范围。
- 下次更快的做法：先用 `curl --max-time 15` 探测 registry，再执行带临时参数的
  `npm install --package-lock-only`；不要重复等待同一条不稳定链路。
- 最终验证结果：使用临时 npm 镜像解析并生成锁文件后，`HOME=/tmp/memoryguard-final-20260906/npm-home npm ci --ignore-scripts --no-audit --no-fund` 成功安装 641 个适用平台包；Hardhat 编译并测试通过，4 passing。锁文件中的 `resolved` 已审查并统一为 `registry.npmjs.org`，未使用本地路径或脚本安装。

## 2026-09-06 — Hardhat 开发依赖的官方审计提示

- 适用环境：同一候选锁文件与 Node `v22.23.0`。
- 执行命令：`npm audit --package-lock-only --json --registry=https://registry.npmjs.org`
  以及只读的 `--omit=dev` 对照。
- 结果：完整开发依赖树报告 47 条提示（18 high、10 moderate、19 low、0
  critical）；直接依赖 `hardhat@2.29.1` 和
  `@nomicfoundation/hardhat-toolbox@5.0.0` 的建议修复涉及跨大版本升级到
  Hardhat `3.15.0` / Toolbox `7.0.0`。`--omit=dev` 的漏洞统计为 0；本项目运行时
  不安装 contracts 开发依赖。
- 处理：本轮不执行 `npm audit fix`，也不自动升级大版本；保留当前直接版本以限定
  变更范围，并在发布记录中明确该开发工具链风险。完整审计 JSON 保存在仓库外的本轮
  release 报告目录，不进入提交。
- 最终验证结果：合同锁文件、Hardhat 编译、4 个合约测试和离线 ABI/Keccak 交叉核验
  均已通过；审计提示不代表合约运行时已部署或链上交易已验证。
